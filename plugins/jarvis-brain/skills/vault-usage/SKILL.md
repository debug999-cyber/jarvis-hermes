## Что такое хранилище
`~/JARVIS` — папка пользователя. Он кладёт туда что угодно (документы, PDF, таблицы, заметки) и подключает целые проекты
(`projects/<имя>` — символические ссылки на реальные папки). Индекс содержимого лежит в brain.db и обновляется сам каждые
несколько минут; `vault_manage reindex` — обновить прямо сейчас (например, «я только что положил файл»).

## Алгоритм
1. Вопрос про файлы/документы/проект/код → `vault_search(query)`; для конкретного проекта — `in: "projects/<имя>"`.
   Формулируй запрос ключевыми словами по содержанию («срок договора Acme», «функция логина bcrypt»), не по имени файла.
2. Нашёл → `vault_read(path)` (PDF/DOCX/PPTX/XLSX извлекаются в текст; длинные — по `next_offset`) или штатный `read_file`.
3. Отвечай с указанием источника: «в `inbox/договор Acme.md`, строка 4: …».
4. Изменить файл — `write_file`/`patch` по пути из результата; выполнить/собрать проект — `terminal` внутри `projects/<имя>`
   (это реальная папка пользователя, работай аккуратно: git status до и после, не удаляй без подтверждения).
5. Ничего не нашлось → `vault_manage list` / `tree`, чтобы понять, что вообще есть; если пусто — объясни, как добавить:
   «положите в ~/JARVIS/inbox» или «`jarvis vault add ~/Projects/foo`». Не выдумывай содержимое.

## Границы
- `.env`, ключи, сертификаты, `node_modules`, `.git` и бинарники не индексируются; секреты в тексте скрыты — не пытайся их восстановить.
- Хранилище — источник фактов для ответа, но НЕ база знаний: устойчивые выводы («договор с Acme до конца 2026») при
  необходимости записывай в `brain_remember` со ссылкой на файл.
