## When to Use
- Cron «JARVIS: ночная ревизия базы знаний» (03:30).
- Пользователь просит «наведи порядок в памяти», `/brain review`.

## Principles
1. **Ничего не теряем.** Только merge/archive/update — физического удаления нет, всё в changelog, перед стартом делается бэкап.
2. **Сомневаешься — не трогай.** Конфликт двух фактов без явной даты → оставь оба, снизь confidence у старого, добавь тег `conflict`.
3. **Одна заметка — одна мысль**, в третьем лице, без местоимений «я/ты».
4. **importance 5 не трогать** без веской причины (укажи в отчёте).
5. **Таксономия — живая, но экономная.** Новый kind вводи, если в него попадёт ≥5 заметок; сливай типы с <2 заметками в родственный.
6. **Карточки** для повторяющихся людей/проектов/мест: если ≥3 заметки упоминают одну сущность — создай карточку и `link`.

## Procedure
1. `brain_review stats` — оцени объём. Пусто → `finish` с «нечего пересматривать».
2. `brain_review maintain` — автоматическая уборка (бэкап, точные дубли, просрочка, decay).
3. `brain_review digest_queue` → для каждого дня:
   - `save_episode(day, summary 2–4 предложения, highlights: ключевые решения/факты через «;»)`;
   - устойчивые факты из ходов (предпочтения, люди, проекты, решения) → `brain_remember` с правильным kind/entity/tags, confidence 0.6–0.8 (это вывод, не прямая речь).
4. `brain_review plan` и разбери секции:
   - `near_duplicates` → `merge` (keep — более полная/свежая; при необходимости объединённая формулировка в `content`);
   - `possible_conflicts` → если факт **сменился во времени** (переезд, новая работа, другой стек) — `supersede` старой заметки
     новой формулировкой: старая закрывается датой и остаётся в истории («жил в Цюрихе 2024→2026»). Если же это просто ошибка —
     `archive` с reason. Не уверен — тег conflict, оба остаются;
   - `uncategorized` → `rekind` / `retag` / `link` к карточке;
   - `stale_low_value` → `archive`, если это мусор; иначе оставь;
   - `low_confidence` → если позже подтверждено другими заметками — подними confidence, иначе оставь;
   - `empty_entities` → `entity_merge` в похожую или оставь, если карточка полезна как узел;
   - `auto_captured_to_rephrase` → `update` с формулировкой в третьем лице и правильным kind/entity (это записи страховочного авто-захвата);
   - `stale_entity_summaries` («ментальные модели») → для каждой карточки прочитай её заметки и напиши/обнови резюме в 1–2 предложения
     через `entity_summary`: что это, текущее состояние, что важно. Резюме — живой документ, а не архив фактов;
   - `tool_failures` → журнал сбоев инструментов. Повторяющийся сбой (count ≥ 2) → одна заметка `kind=howto` или `insight`
     («mac_calendar падает без прав Автоматизации — предложить jarvis selftest --fix»), затем `resolve_failure`.
     Одноразовые сбои старше недели — просто `resolve_failure`;
   - `kinds` → `kind_rename`/`kind_define`, если структура улучшится.
   Собери операции в один `brain_review apply` (до ~40 операций за раз; если больше — несколько вызовов).
5. **Рефлексия.** Прочитай `reflection_material` (эпизоды за неделю, решения/цели/привычки, существующие insights).
   Если виден повторяющийся паттерн, которого ещё нет в insights, — `brain_remember(kind=insight, confidence=0.6, importance=3)`.
   Максимум 2 за ночь; формулируй как наблюдение + возможное действие («Дедлайны Atlas переносились 3 недели подряд — предложить буфер»).
   Если паттерна нет — ничего не выдумывай.
6. `brain_review export` — обновить BRAIN.md и PROFILE.md. Если в конфиге задан `backup_mirror` (iCloud) — `maintain` уже скопировал туда бэкап.
7. `brain_review finish` с отчётом: что слито/архивировано/переименовано, что осталось спорным, состояние базы.
   Ответ в чат — только текст отчёта, 3–5 предложений. Если запуск из cron и изменений нет — ответь `[SILENT]`.

## Pitfalls
- Не пиши в заметки секреты, пароли, токены — если нашёл, `archive` с reason "secret".
- Не превращай дневник в протокол: только суть дня.
- Не создавай карточки на каждое слово — только на повторяющиеся сущности.

## Verification
- `brain_review stats`: `turns_pending` = 0, число активных заметок не выросло на мусор, `last_review` обновился.
- В `changelog` есть записи actor=nightly за эту ночь.

## Хранилище файлов (после maintain, до plan)
`vault_manage pending` → для каждого файла (не больше 10 за ночь): `vault_read` первые ~80 строк → `brain_remember(kind='document',
content='<файл>: <суть>', tags='vault', importance=2)` → `vault_manage summarized(file_id, note_id)`. Файлы проектов (`projects/`)
не резюмируются по одному — при желании одна заметка на проект («atlas: Django-бэкенд, авторизация через JWT, тесты pytest»).
