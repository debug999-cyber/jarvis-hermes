## 1.8.0 — хранилище файлов, событийная проактивность, doctor --fix, установка одной командой

### Главное: память теперь и для ваших файлов и проектов
- **Хранилище `~/JARVIS`** (`plugins/jarvis-brain/vault.py`): кладите любые файлы (`inbox/`) и подключайте проекты
  (`jarvis vault add <папка>` → symlink в `projects/`). Индекс содержимого в той же `brain.db` (таблицы `files`/`file_chunks`,
  FTS5 `files_fts`, BM25): текст/код ~70 расширений, PDF (`pdftotext`), DOCX/RTF/Pages (`textutil`), PPTX/XLSX (XML из zip).
  Пропуск `node_modules/.git/venv`, файлов > 5 МБ и **секретов** (`.env`, ключи, сертификаты); токены в тексте → `[скрыто]`.
- Инструменты агента `vault_search` / `vault_read` / `vault_manage`; блок `[JARVIS vault]` с релевантными фрагментами в контексте
  каждого хода; навык `vault-usage`; правило в SOUL.md («вопрос про мои файлы → сначала vault_search»).
- Фоновая переиндексация (`vault_scan_minutes`, по умолчанию 10), `jarvis vault status|open|add|remove|list|tree|search|read|reindex`,
  виджет «Файлы» и раздел хранилища в панели базы знаний HUD, событие `vault.update`. Документация: `docs/VAULT.md`.

### Проактивность стала событийной
- `plugins/jarvis-core/triggers.py`: каждые 60 с без LLM — **новые файлы в inbox** (→ модель читает и предлагает, что сделать),
  **возвращение к Mac** после ≥ 90 мин простоя (первый раз утром → брифинг, иначе тихая проверка), **мало места на диске**,
  **питание отключено при ≤ 30 %**. LLM зовётся не чаще раза в 15 мин и только по поводу; в focus/night — только срочное.
  Состояние переживает рестарт (`triggers.json`). Cron-heartbeat остаётся страховкой раз в 3 ч (был каждые 45 мин).
- **Контекст экрана**: «что у меня на экране / посмотри сюда / что это за ошибка» → скриншот снимается автоматически,
  модели подсказывается сразу вызвать `vision_analyze`; без права «Запись экрана» — объяснение, как выдать.
- **Обратная связь памяти**: если JARVIS подсказал факт из базы, а вы ответили «это не так / устарело» — уверенность заметки
  падает (тег `verify`, просьба уточнить и исправить); «верно» — растёт. `Brain.feedback()`.

### Диагностика и установка для новичка
- **`jarvis doctor [--fix|--quick|--json]`** (`scripts/doctor.py`): Hermes, **модель реально отвечает** (ping), плагины включены
  и компилируются, `.env` API-сервера, gateway :8642, HUD :8765 + совпадение ключа, launchd, права macOS (selftest), хранилище,
  версия/обновления. `--fix` дописывает `.env`, включает плагины, поднимает сервисы, грузит агенты, создаёт `~/JARVIS`,
  открывает панели прав. Старый `hermes doctor` — `jarvis doctor --hermes`.
- **Установщик проверяет модель** коротким ping'ом после настройки и предлагает `hermes model`, если она не отвечает
  (частая причина «ничего не работает»). В конце — `doctor --quick --fix`.
- **`get.sh`**: `curl -fsSL …/get.sh | bash` — скачивает последний релиз (git или zip), ставит Xcode CLT при необходимости,
  запускает `install.sh` интерактивно (stdin из `/dev/tty`).
- **Релиз с готовым JARVIS.app**: `release.yml` собирает приложение на macOS-раннере и кладёт `app/prebuilt/JARVIS.app.zip`
  в zip релиза (+ отдельным артефактом); `install.sh` использует его, если нет `swiftc`.
- **Мастер первого запуска в JARVIS.app**: 4 шага-окна (где значок → модель → права → папка файлов и HUD) на основе
  `doctor --json`; пункты меню «Мастер настройки…», «Диагностика и починка» (⌘D), «Папка файлов ~/JARVIS» (⌘F).
- **Быстрые команды** (`jarvis shortcuts`, `scripts/make_shortcuts.py`): «Спросить JARVIS» (Siri), «В хранилище JARVIS»

  подписываются локально (`shortcuts sign`), импорт одним кликом.

## 1.7.0 — стабильный релиз: аудит и исправления
Полный проход по коду (ruff/pyflakes/shellcheck + ручной разбор сценариев). Ниже — всё, что было найдено и исправлено.

### Критичное
- **Инъекция в AppleScript через `mac_type`**: модификаторы клавиш (`modifiers`) подставлялись в скрипт как есть.
  Теперь строгий allow-list (`command/option/control/shift` + синонимы), незнакомое — ошибка без выполнения.
- **Нестандартный `HERMES_HOME` ломал данные**: плагины `jarvis-core`/`jarvis-brain` (fallback без `plugin_storage`),
  кэш скриншотов/камеры `jarvis-macos`, `brain_db` и разрешённые корни `/file` в HUD, `export_path` — всё было
  зашито на `~/.hermes`. Теперь везде `$HERMES_HOME` (пустые значения в конфиге = «по умолчанию от HERMES_HOME»).
  Тест `test_no_hardcoded_hermes_home_in_code` не даст этому вернуться.
- **`jarvis update` из демона мог «положить» сервисы**: `restart_services` дёргал `launchctl kickstart`, `jarvis hud restart`
  и `hermes gateway restart` подряд (двойной перезапуск, гонка с KeepAlive), а отсутствие бинарника роняло updater
  исключением уже после установки. Теперь: под launchd — только `kickstart`, иначе — обычный перезапуск; всё best-effort.

### Автообновление и приложение
- После обновления **пересобирается JARVIS.app** из свежего `app.src` (install.sh при апдейте идёт с `--no-app`),
  запущенное приложение перезапускается отдельным процессом — обновление, начатое из меню, больше не убивает само себя.
- JARVIS.app: если HUD лежит, состояние API проверяется напрямую по `:8642/health` (раньше показывало «API ○» ошибочно);
  порт HUD берётся из `JARVIS_HUD_PORT`.

### CLI `jarvis`
- `hud start/stop/restart/status` понимают, что HUD запущен **launchd**'ом (раньше `hud stop` под launchd был бесполезен —
  KeepAlive поднимал его снова, а `hud start` запускал второй экземпляр на занятом порту).
- `gateway start/stop/restart` — то же самое для gateway.
- Понятные ошибки вместо стека bash: нет `HERMES_HOME`, нет `sqlite3`, нет базы знаний, нет бэкапов, `jarvis ask` без вопроса,
  `jarvis app open/debug` без собранного приложения. `help`/`version` работают без установки.
- `jarvis app build` закрывает старое приложение перед сборкой.

### HUD
- Чат: ошибка провайдера внутри SSE-потока (`{"error": …}`) теперь показывается человеку; пустой ответ модели — объясняется,
  а не молча остаётся пустым экраном.
- Лимит тела POST-запроса 2 МБ; upstream-соединение к Hermes закрывается при обрыве браузера.
- Подсказки об ошибках ссылаются на реальный `$HERMES_HOME/.env`, а не на `~/.hermes`.

### Установщик
- `--no-brew-tools` больше не требует Homebrew (раньше падал, если brew нет, даже с этим флагом).
- Проверка целостности архива до копирования плагинов; генерация `API_SERVER_KEY` без `openssl`;
  плагины включаются командой `hermes plugins enable`, если после merge не отобразились.

### Плагины
- `jarvis-brain`: открытие базы в хуках `pre/post_llm_call` обёрнуто в try (сбой диска не ломал ход агента);
  словарь `_turn_tools` не растёт бесконечно при сессиях без `post_llm_call`.
- `jarvis-macos`: `raise … from e` для читаемых трейсбеков; `hud_url` в настройках (для `mac_say stop`).

### Качество
- `ruff.toml` + `ruff check .` чисто; `shellcheck` чисто; CI: ruff + shellcheck (Linux) + сборка JARVIS.app (macOS) на каждый push.
- +15 тестов (`tests/test_release_audit.py`, `mac_type`): 89 passed, 2 skipped (macOS-only).
- Документация: USAGE/INSTALL/TROUBLESHOOTING синхронизированы с реальными командами и флагами; README — статус «стабильный релиз».

## 1.6.1 — повторы и «не заткнуть»
Отзыв: «несколько раз повторяет одно и то же, и то, что он говорит, невозможно остановить».

### Почему повторялось
- Ход агента приходил на HUD **тремя путями**: плагин `jarvis-core` (pre/post_llm_call), хук `jarvis-boot`
  (agent:start/end) и прокси `/api/chat`. Текст отрисовывался и озвучивался по несколько раз.
- Контекст «доступно обновление» подмешивался в **каждый** ход — модель послушно напоминала о нём каждый раз.
- Модель вызывала `mac_say` поверх TTS Hermes: одну фразу говорили два голоса, и `say` нельзя было прервать.

### Исправлено
- HUD-сервер отбрасывает дубли `turn.*/stream.*`, пока идёт чат через прокси; `jarvis-boot` больше не зеркалит ходы;
  HUD не озвучивает и не показывает один и тот же ответ дважды.
- Напоминание об обновлении — один раз за процесс.
- `mac_say`: новая фраза перебивает предыдущую; `action=stop` глушит `say`/`afplay`/озвучку HUD; описание инструмента
  запрещает использовать его для обычных ответов. SOUL.md и навык voice-etiquette: «ничего не повторяй», «стоп» = замолчать.

### Как остановить речь теперь
`Esc` или кнопка ■ в HUD · «Замолчать» в меню ◉ (⌘.) · `jarvis hush` в терминале · голосом «стоп»/«хватит»
(барж-ин Hermes: просто начните говорить).

## 1.6.0 — HUD 2.0: рабочий стол на реальных данных, исправления
Переработка после отзыва «выглядит дёшево, многое не работает». HUD теперь — спокойный дашборд в духе macOS

- Новый экран: слева «Сегодня» (Calendar.app) и «Знания» (brain.db), в центре сфера + диалог, справа «Система»
  (батарея `pmset`, Focus macOS, модель из `config.yaml`, версия) и «Таймеры».
- Таймеры можно ставить и отменять в HUD; они лежат в общем `state.json` с `jarvis_timer`, и HUD-сервер сам их

- Новые эндпоинты: `GET /api/dashboard`, `POST /api/timer`, `POST /api/mode`; флаг `--demo` для скриншотов.
- Ошибки чата объясняются по-человечески («405 — неверный endpoint кастомной модели, выполните `hermes model`»)
  вместо `HTTP 405: Error code: 405`.

### Исправления
- **BOOT-панели с «HTTP 405»**: хук `jarvis-boot` больше не выводит ошибки модели на экран (только в лог), панель
  имеет стабильный id и заменяется, а не плодится при каждом рестарте gateway.
- **«ВЫ: [IMPORTANT: The user has invoked the jarvis/heartbeat skill…]»**: cron/heartbeat-сессии больше не
  показываются как реплики пользователя; их результат идёт в ленту активности и карточку «Фоновая задача», `NO_REPLY` скрывается.
- При перезагрузке страницы HUD восстанавливает только актуальные панели (после последнего `panel.clear`, без ttl,
  не старше 30 мин), а не всю историю событий — исчезли «воскресающие» старые карточки и дубли тостов.
- Счётчик ходов/сессия больше не портятся cron-сессиями.

### Приложение и документация
- Иконка JARVIS.app — сфера в стиле нового HUD. Баннер и скриншоты обновлены. Таблица виджетов и клавиш в `docs/USAGE.md`.
