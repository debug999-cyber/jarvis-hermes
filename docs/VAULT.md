# Хранилище файлов и проектов (`~/JARVIS`)

> База знаний JARVIS — это не только его собственные заметки. С 1.8 туда можно **класть любые файлы и целые проекты**,
> и JARVIS имеет к ним полный доступ: ищет по содержимому, читает PDF/Word/Excel/PowerPoint, правит код, запускает тесты.

## Как пользоваться (без терминала)

1. **Откройте папку**: меню ◉ → «Папка файлов ~/JARVIS» (или `jarvis vault open`). Появится:
   ```
   ~/JARVIS/
     README.md      ← короткая шпаргалка
     inbox/         ← сюда бросайте что угодно: договоры, PDF, заметки, презентации, таблицы
     projects/      ← ссылки на ваши проекты (папки остаются на своих местах)
   ```
2. **Перетащите файлы** в `inbox/` (или любую свою подпапку). Через минуту JARVIS сам заметит новое, прочитает и скажет,
   что это и что с этим можно сделать («это договор с Acme до конца 2026 — записать срок в память?»).
3. **Подключите проект**: `jarvis vault add ~/Projects/atlas` — в `projects/atlas` появится ссылка, содержимое проиндексируется
   (без `node_modules`, `.git`, `venv`, бинарников и секретов). Отключить: `jarvis vault remove atlas`.
4. **Спрашивайте как обычно**: «что в договоре с Acme про сроки?», «где в atlas реализован логин?», «сделай тезисы из
   презентации в inbox», «запусти тесты в проекте atlas». JARVIS сначала ищет по индексу, потом читает нужные места.

Из Finder: правый клик на файле → **Быстрые действия → «В хранилище JARVIS»** (ставится командой `jarvis shortcuts`).

## Что индексируется

| Тип | Как | Нужно |
|---|---|---|
| Текст, Markdown, код (≈70 расширений), JSON/YAML/CSV, логи, субтитры, `.ics`/`.vcf` | напрямую | — |
| PDF | `pdftotext` | `brew install poppler` (установщик ставит) |
| Word `.docx/.doc`, RTF, Pages, ODT, webarchive | `textutil` (встроен в macOS) | — |
| PowerPoint `.pptx`, Excel `.xlsx` | разбор XML внутри zip | — |
| Картинки, видео, архивы, бинарники | только имя файла в дереве | — |

Пропускаются: `node_modules`, `.git`, `venv`, `__pycache__`, `build/dist/target`, кэши; файлы > 5 МБ;
**секреты** — `.env`, `*.pem`, `*.key`, `id_rsa`, сертификаты, keychain. В тексте остальных файлов похожие на пароли и
токены фрагменты заменяются на `[скрыто]` **в индексе** (сам файл не трогается).

Индекс живёт в той же базе, что и память (`brain.db`, таблицы `files`/`file_chunks` + FTS5). Обновляется в фоне каждые
10 минут (`vault_scan_minutes`), при добавлении проекта, по `jarvis vault reindex` и когда JARVIS сам вызывает
`vault_manage reindex` («я только что положил файл»).

## Как этим пользуется агент

| Инструмент | Что делает |
|---|---|
| `vault_search(query, in?, ext?, limit?)` | полнотекстовый поиск по содержимому (BM25, префиксы слов, русский/английский); возвращает файл, строку, фрагмент |
| `vault_read(path, offset?, limit?)` | текст файла (PDF/DOCX/PPTX/XLSX уже сконвертированы), постранично |
| `vault_manage(action=status\|list\|tree\|reindex\|add\|remove)` | состояние, дерево, переиндексация, подключение проектов |
| обычные `read_file` / `write_file` / `patch` / `terminal` | по путям из результатов — править и запускать проекты |

В каждый ход, где в сообщении ≥ 3 слов, JARVIS получает блок `[JARVIS vault]` с 1–3 лучшими фрагментами — поэтому часто
отвечает «по вашим файлам» даже без явной просьбы. Правила — в навыке `vault-usage` и в SOUL.md: сначала поиск, потом чтение,
ответ со ссылкой на файл и строку, никаких необратимых действий без подтверждения.

## Команды

```
jarvis vault                 статус: сколько файлов, проекты, последний скан, есть ли pdftotext
jarvis vault open            создать (если нет) и открыть ~/JARVIS в Finder
jarvis vault add <папка>     подключить проект (symlink в projects/) и проиндексировать
jarvis vault remove <имя>    отключить проект
jarvis vault list [--json]   все файлы в индексе
jarvis vault tree [путь]     дерево
jarvis vault search "слова"  поиск из терминала
jarvis vault read <файл>     извлечённый текст
jarvis vault reindex [--force]
```

Настройки (`config.yaml → plugins.jarvis-brain`): `vault_dir` (другая папка; или `JARVIS_VAULT_DIR`), `vault_context`
(подмешивать ли в контекст), `vault_scan_minutes`.

## Приватность

Всё локально: индекс — в `brain.db` на вашем Mac, в модель уходят только фрагменты, релевантные текущему вопросу
(как и любой `read_file`). Файлы с секретами не индексируются вовсе; бэкапы базы (`jarvis brain backup`) содержат индекс,
но не сами файлы.
